1# Architecture: HappyRobot Inbound Carrier Sales POC23## Context45HappyRobot Logistics wants an AI voice agent to take the first leg of inbound carrier calls:6MC lookup → FMCSA authority → OTP → load match → negotiate (≤3 rounds, never exceed or leak7`max_rate`) → tentative reservation → mocked senior-rep handoff → structured log. Source of8requirements: `FDE_Technical_Challenge_-_Inbound_Carrier_Sales.pdf`; summary in `PROJECT_GUIDE.md`.910The project folder has no code yet. `REFERENCES/happyrobot-mcp-us-workflows.mcpb` is a thin11`mcp-remote` proxy to `https://mcp.platform.happyrobot.ai/workflows/mcp` (manage workflows,12integrations, testing). Installed in Claude, it lets us build and test the workflow in the13user's workspace directly instead of by hand. `REFERENCES/Lesson4/5.ipynb` are LiveKit course14notebooks, not relevant to the HappyRobot build.1516Decisions made: **Python + FastAPI** bridge, **Fly.io** deploy, **hold-then-book** (LOAD_BOOK17only after the mocked senior rep confirms).1819## Core design principle2021The LLM talks; deterministic code decides. Anything with a compliance rule (OTP, rate ceiling,22round limit, booking) is enforced in the bridge, never in the prompt. The agent only ever23sees what it may say out loud; `max_rate`, OTP codes and raw TMS frames never reach it.2425## Components2627```28Carrier (web call)29   │30HappyRobot workflow ── Inbound Voice Agent + tools ──HTTPS + API key──► Bridge (FastAPI, Fly.io)31   │   │                                                                  ├─ TCP ──► Legacy TMS32   │   └─ SMS/email node (sends OTP from hidden tool field)                ├─ HTTPS ─► FMCSA QCMobile33   │                                                                      └─ Twin API (state + events)34   └─ post-call: extract/classify → Twin write35Twin (Postgres) ◄────── HappyRobot App (Next.js dashboard, server-side Twin gateway)36                            └─ "Senior rep queue" action ──API key──► Bridge /holds/{id}/confirm → LOAD_BOOK37```3839### 1. Bridge service (`bridge/`, Python 3.12, FastAPI, httpx, pydantic)40Stateless compute; all state lives in Twin so no external DB is needed.4142| Endpoint | What it enforces |43|---|---|44| `POST /carriers/verify` | MC → FMCSA QCMobile; returns `eligible`, legal name, reason. Normalizes "MC 123" etc. |45| `POST /otp/send` | Only if call already passed FMCSA. Generates 6-digit code, stores **hash** + expiry (5 min) in Twin, sends to the **contact on file** (Twin carrier registry, seeded; never a number the caller dictates). Returns code only in a hidden field for the SMS/email node. Rate-limited (2 sends/call). |46| `POST /otp/verify` | Max 3 attempts, constant-time compare, marks call `otp_verified`. Hard fail ends the call. |47| `POST /loads/search` | Requires `otp_verified` for the call_id. LOAD_QUERY by lane/equipment, drops held/booked/past-pickup loads, returns pitch fields only (no `MAX_BUY`). Ranks top 1-3. |48| `POST /negotiate` | Input: call_id, load_id, carrier ask. Server tracks round (1-3), computes response from `max_rate` with a concession schedule that never lands predictably on the ceiling; returns `accept` / `counter <price>` / `final_reject`. Round 4 is impossible. |49| `POST /holds` | Creates tentative hold in Twin at agreed rate (only a rate the negotiator accepted). |50| `POST /holds/{id}/confirm` · `/release` | Called from the App by the "senior rep"; confirm → LOAD_BOOK (idempotent). |51| `GET /health`, `POST /debug/echo` | Liveness + TMS DEBUG_ECHO diagnostic. |5253All routes require `Authorization: Bearer <key>` (separate keys for HappyRobot and the App);54`/health` exempt. Every call writes a `call_events` row to Twin (tool, latency, outcome).5556**TMS client (`bridge/tms/`)** - the riskiest piece, built and tested first:57- One TCP connection per request; connect timeout 3 s, total read deadline ~6 s; reject frames58  > 4096 bytes; read until `END\r\n` or `ERR|...`.59- Parser tolerant of right-padding, arbitrary field order, unknown fields; partial (no `END`),60  garbled or wrong-shaped responses → typed `TmsMalformed`, never a crash.61- Reads (QUERY/GET) retry up to 2× with jittered backoff inside the voice latency budget;62  short-lived cache (~60 s) of last good query per lane as a fallback.63- LOAD_BOOK never retried blindly: on timeout, LOAD_GET to check state, then retry once;64  `ALREADY_BOOKED` on our own hold = success.65- Simple circuit breaker; the agent gets `{"status":"tms_unavailable"}` and says so politely66  instead of inventing loads.6768### 2.
