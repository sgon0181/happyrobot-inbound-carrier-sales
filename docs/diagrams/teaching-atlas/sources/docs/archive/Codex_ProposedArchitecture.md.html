HappyRobot owns the conversation**3738Configure the web-call trigger, inbound voice agent, prompt and tools.3940The agent can request operations such as:4142- Check carrier authority.43- Send and verify an OTP.44- Search and inspect loads.45- Request an offer or counteroffer.46- Request booking and mocked handoff.4748**The agent asks for actions; the backend decides whether they are permitted.** A caller persuading the model cannot override the backend's rules.4950**2. Your backend owns the rules and integrations**5152Use **Python with FastAPI**, Pydantic for request validation, an HTTP client for external APIs, and Python's TCP networking support for the TMS. FastAPI supports asynchronous requests, which suits waiting on these external systems. [FastAPI documentation](https://fastapi.tiangolo.com/async/)5354Keep four modules inside that service:5556| Module | Responsibility |57|---|---|58| **Verification** | FMCSA lookup, OTP generation/checking, expiry and attempt limits. |59| **Load integration** | Translate structured requests into TMS commands and parse responses. |60| **Negotiation and booking** | Enforce verification gates, permitted prices, counter limits and booking prerequisites. |61| **Persistence** | Read call state and record actions, results and failures in Twin. |6263HappyRobot supplies the agent infrastructure. This design does not require a separate LiveKit or LangGraph agent.6465**3. Twin owns your solution's durable records**6667Start with these logical tables:6869| Table | Stores |70|---|---|71| `calls` | Call ID, carrier MC, verification status, selected load, counter count and outcome. |72| `call_events` | Timestamped activity: checks, searches, offers, errors and handoffs. |73| `otp_challenges` | Code hash, expiry, attempts and association with the call and carrier. |74| `booking_attempts` | Requested booking, agreed rate, request identifier, result and uncertainty. |7576The **TMS remains the source of truth for loads and booking responses**. [Twin documentation](https://docs.happyrobot.ai/twin/overview)7980**4. Apps gives the operations manager a usable interface**8182Build the dashboard inside HappyRobot Apps. Initially show:8384- Recent calls and their outcomes.85- Verification and negotiation results.86- Load, agreed rate and booking reference.87- Failed integrations and bookings requiring review.88- Basic KPIs, such as booking success and verification failures.8990Operator actions should call the backend, so they follow the same business rules. Credentials stay in server-side code.9192**5. The backend must enforce these boundaries**9394- **Verification:** search and booking check stored verification state. They never trust a model-supplied `verified: true`.95- **Pricing:** return only approved offers and carrier-facing load details. Keep the confidential ceiling and raw pricing records outside the conversational model.96- **Negotiation:** count counter rounds across the entire call, including load switches.97- **Failures:** use bounded timeouts and limited retries for reads. A booking timeout means **unknown outcome**, because the TMS may already have committed it. Do not blindly resend.98- **Repeated requests:** identify duplicate actions and prevent repeated bookings or extra OTP sends.99100Verify Twin's support for safe conditional state updates early. Start with one backend instance for the POC, with its concurrency limits documented.101102**6.
