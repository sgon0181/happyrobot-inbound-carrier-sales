Wire protocol and parsing2728This is raw TCP. Open a fresh connection per request. Encode ASCII, put `CMD` first, use uppercase keys, include `AUTH` every time, and terminate with CRLF bytes. Below, `\r\n` represents those bytes; angle brackets mark placeholders.2930The reader uses plain TCP; no TLS negotiation is documented. The HTTPS handbook does not encrypt that socket. Keep TMS access server-side, never in a browser client.3132```text33CMD:<command>|AUTH:<token>|KEY:<value>\r\n34```3536- Split fields on `|`, then split each field at its first `:`. Reject pipes and CR/LF in input values. Unknown request fields are accepted but discarded, so a successful reply does not prove a filter was applied.37- Parse responses by key, not field order, column width or example ID length. Response values are right-padded with spaces; trim padding and preserve legitimate blank values such as `NOTES`. Preserve IDs and booking references as opaque strings.38- TCP chunks are not records. Accumulate bytes until complete CRLF-terminated lines arrive, with explicit size and time bounds.39- Success is zero or more record lines followed by a separate, exact `END\r\n` line. `END\r\n` alone is a valid empty result. A line such as `NOTES:WEEKEND\r\n` is not a terminator. Stop at `END`, without waiting for connection closure.40- Error is exactly one `ERR|CODE:<code>|MSG:<message>\r\n` line, without `END`. Validate framing and required fields; never treat a partial reply as an empty search or a completed booking.41- The handbook documents a 4096-byte frame including terminator and a 30-second idle timeout. Live replies reached 7,941 bytes in total, so enforce the frame bound per line plus a separate total-response bound. The current reader's total bound is 1 MiB; the production adapter still needs its own chosen limit.42- Ignore unknown response keys after structural validation, but require the fields needed for the requested operation. `DEBUG_ECHO` has a bare `ECHO` record prefix, so a parser that demands `KEY:VALUE` for every segment cannot parse that command.4344## 3. Commands, fields and codes4546### `DEBUG_ECHO`: diagnose transport and authentication4748```text49CMD:DEBUG_ECHO|AUTH:<token>|MSG:HELLO\r\n50ECHO|AUTH:OK|FIELDS_PARSED:3|MSG:HELLO\r\n51END\r\n52```5354`MSG` is echoed as supplied. Additional `KEY:VALUE` fields count toward `FIELDS_PARSED` and are discarded; the count includes `CMD` and `AUTH`. This command bypasses the fault-injection layer. It proves basic framing, reachability and authentication, not healthy load queries or booking behavior.5556### `LOAD_QUERY`: find candidate loads5758```text59CMD:LOAD_QUERY|AUTH:<token>|ORIG_STATE:TX|DEST_STATE:CA|EQTYPE:DRY_VAN|MAX_RESULTS:3\r\n60```6162Supply at least one actual search filter. `MAX_RESULTS` limits results; it is not a lane/equipment filter. Concrete filter names shown by the handbook are `ORIG_STATE`, `DEST_STATE`, `ORIG_CITY` and `EQTYPE`. The description also promises destination-city, ZIP and pickup filtering without listing every wire key. **Do not invent missing parameter names.** `PICKUP_DATE:YYYYMMDD` is supported by the local study. Unproven names such as `PICKUP_FROM` can be silently ignored.6364Normalize state and equipment to uppercase. City matching is forgiving; the study observed case-insensitive partial city matching. State and ZIP matching are stricter. Supported equipment observed with this token:6566| Spoken equipment | `EQTYPE` |67|---|---|68| Van, dry van | `DRY_VAN` |69| Reefer, refrigerated | `REEFER` |70| Flatbed | `FLATBED` |71| Step deck | `STEP_DECK` |72| Power only | `POWER_ONLY` |7374The handbook does not publish a complete equipment enum. It says unsupported equipment yields no rows; this token instead returned `MISSING_FIELD` during the study. Validate equipment before querying and handle both outcomes. `MAX_RESULTS` defaults, server caps, pagination and sort order are not established. Recheck returned matches and sort deliberately, rather than trusting ignored filters or server order.7576The handbook calls this the open board, but live searches returned already `PENDING` loads. Offer only explicitly `OPEN` records after schedule and local-block checks. Each result is a summary with `LOAD_ID`, origin/destination city/state/ZIP, `PICKUP_DT`, `EQTYPE`, `RATE`, `MILES` and `STATUS`, followed by `END`. The study's query summaries never contained `MAX_BUY`.7778### `LOAD_GET`: fetch full details before pricing7980```text81CMD:LOAD_GET|AUTH:<token>|LOAD_ID:<load_id>\r\n82```8384| Fields | Meaning and handling |85|---|---|86| `LOAD_ID` | Opaque load identifier; validate it matches the request. |87| `ORIG_CITY`, `ORIG_STATE`, `ORIG_ZIP` | Pickup location; retain ZIP as text to preserve leading zeros. |88| `DEST_CITY`, `DEST_STATE`, `DEST_ZIP` | Delivery location. These are response keys, not proof of accepted query keys. |89| `PICKUP_DT`, `DELIVERY_DT` | Compact date/time values, shown as `YYYYMMDDhhmmss`; timezone is unconfirmed. |90| `EQTYPE`, `MILES`, `STATUS` | Equipment, mileage and current server status; validate known values and handle unfamiliar ones explicitly. |91| `RATE` | Posted price, provisionally mapped to PDF `loadboard_rate`. |92| `MAX_BUY` | Optional, token-enabled internal price; provisionally mapped to PDF `max_rate` under decision D-10. Never expose it to the runtime voice agent. |93| `WEIGHT`, `COMMODITY`, `PIECES`, `DIMS`, `NOTES` | Cargo and instructions. `COMMODITY` and `DIMS` are free text; blank notes are valid. Validate numeric fields and units before mapping. |9495`LOAD_GET` can return booked or past-pickup loads, so a successful lookup does not mean availability. The handbook does not define a complete status enum. Require explicit `STATUS:OPEN` and a usable future pickup schedule before offering a load; status alone cannot clear a local pending/unknown block.9697The study found whole-number `RATE` and `MAX_BUY` on all 302 full records, with `MAX_BUY` above `RATE`; handbook examples show the reverse. Neither proves booking-rate units, precision, accepted bounds or enforcement of the ceiling. If `MAX_BUY` is missing or unusable, route to pricing review; never invent a ceiling from `RATE`. Live dimensions used feet while the PDF asks for inches, so convert deliberately. Contradictory notes must be flagged for the rep, not silently rewritten; extra-charge treatment is unconfirmed.9899### `LOAD_BOOK`: submit a booking, with a side effect100101Schema only, not a command to run against a sample load:102103```text104CMD:LOAD_BOOK|AUTH:<token>|LOAD_ID:<load_id>|MC_NUM:<carrier_mc>|AGREED_RATE:<validated_exact_rate>\r\n105```106107All three payload fields are required. The handbook shows a numeric `MC_NUM` example, but does not fully document MC validation. Normalize the approved carrier's MC in the service. Validate an exact, finite, positive whole native numeric value against the fresh internal ceiling, then serialize canonical integer text. The live sample accepted `.00` but rejected a nonzero fraction; do not silently round. Currency/scale, full grammar and accepted bounds remain unresolved; no test authorizes exceeding the ceiling.108109The documented success record contains `LOAD_ID`, `BOOKING_REF`, `STATUS:BOOKED` and `TIMESTAMP`, then `END`. The timestamp uses `YYYYMMDDhhmmss` in UTC; the booking reference is server-assigned and opaque. Booking state is token-scoped, so another token's view can differ. `ALREADY_BOOKED` is monotonic for a token/load, but does not prove the current carrier and rate own that booking.110111**Observed behavior differs:** the [booking evidence](../tms-contract.md#booking-experiments-2026-10-31) records four reference-bearing `PENDING` acknowledgements, an explicit fractional-rate rejection, and a separate duplicate probe returning `ALREADY_BOOKED` without finalizing. Four loads stayed pending roughly 40 minutes after their initial acknowledgements. Readbacks omitted booking reference/MC/agreed rate. Those tests used MC 872144, which FMCSA shows as inactive. One later attempt with active MC 138328 lost its reply while the load read `PENDING`, so the cause remains open. No final-confirmation operation or live `BOOKED` transition was established. Persist the direct receipt as `ACK_PENDING`; a reference alone does not increment confirmed-booking KPIs. [Sanitized fixtures](fixtures/README.md) preserve all six observed replies.112113No hold, cancellation, release, confirmation or idempotency-key command is documented. Local booking and write-intent IDs coordinate our service only. A timed-out write may have committed: never blindly retry `LOAD_BOOK`, including after restart. Record an unknown outcome and reconcile using authoritative carrier/rate/booking evidence; a booked status or `ALREADY_BOOKED` alone is insufficient.114115### Error handling116117Codes are non-exhaustive. The service verifies FMCSA eligibility and a fresh OTP for the trusted call before returning any load details. Coding-agent access to this reference does not bypass runtime verification.1332. Normalize lane/equipment, query, then fetch full details for candidates. Check filters, schedule, availability and our own active bookings; offer at most three ranked candidates through an allowlisted response.1343. The backend applies the versioned pricing policy, with no missing-ceiling fallback. At most three counter rounds total per call; failed negotiation ends without handoff. The runtime agent receives only permitted details and the approved offer.1354. Reserve the agreed carrier, load and exact rate by inserting the booking row, then hand off. **D-22:** `LOAD_BOOK` is sent when the senior rep confirms, never during the call. This is an explicit decision, not Luke's mandate. No TMS hold or finalization command is inferred. See [architecture section 10](../../ARCHITECTURE.md#10-reservation-and-confirm).1365. At Confirm, re-read the load and ceiling, win the version-checked write to `SUBMITTING`, then send `LOAD_BOOK` once. Persist the actual receipt as `ACK_PENDING`, authoritative `CONFIRMED` or transport-`UNKNOWN`. Keep pending and unknown loads blocked from new offers. Operator annotations alone do not unblock them. Never overstate finality.137138Fault injection can accept a request then stay silent, truncate a response, corrupt framing/fields, or delay closing a complete connection. Faults have no reliable marker and may vary. A complete `DEBUG_ECHO` does not rule them out.139140Reads may retry on bounded transient failures with a fresh connection, up to two retries and jittered backoff inside the architecture's approximate 6-second read budget. Do not spend 30 seconds waiting for server idle close, accept truncated data, or pitch stale cached inventory. Validate the production parser against empty results, padding, reordered fields, unknown keys/codes, split chunks, oversized lines, bad framing and exact terminators. Use fake-server tests for write failures and ambiguous outcomes. Reserve disposable inventory in [the evidence record](../tms-contract.md#booking-test-inventory) before any later live booking test.141142## 5.
